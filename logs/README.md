# 临时调试日志目录

本目录用于记录开发、联调和真机排查过程中的**临时诊断日志**，不是生产日志目录，也不用于替代 `CHANGELOG.md`。

> 注意：`pages/logs/` 是未在 `app.json` 注册的历史页面，和本目录无关。

## 使用边界

- 适用于：上传、下载、网络请求、页面生命周期、权限等问题的临时排查。
- 不适用于：功能变更记录、发布说明、长期架构文档。功能变更仍写入根目录 `CHANGELOG.md`。
- 小程序运行时代码无法直接写入本目录。排查时先把 Console 输出复制到本目录的记录文件中，再提交或分享。
- 云函数侧日志在云开发控制台查看；客户端直传云存储（如 `wx.cloud.uploadFile`）不会出现在云函数日志中。

## 文件命名

```text
logs/YYYY-MM-DD-<topic>.md
```

示例：

```text
logs/2026-11-05-video-upload.md
```

一次问题或一次排查一个文件，不要把多个无关问题堆在同一文件。

## Console 日志格式

统一使用一行 JSON，便于复制和检索：

```text
[module] {"ts":"2026-11-05T06:44:09.123Z","level":"INFO","stage":"upload-video:start","elapsedMs":0,"size":123456}
```

约定：

| 字段 | 说明 |
|---|---|
| `module` | 固定前缀，如 `[video-upload]` |
| `ts` | ISO 8601 时间，UTC |
| `level` | `INFO` / `WARN` / `ERROR` |
| `stage` | 阶段名，建议 `模块:动作`，如 `upload-video:progress` |
| `elapsedMs` | 从本次操作开始到当前阶段的毫秒数 |
| 其他字段 | 文件大小、进度、`cloudPath`、`errMsg`、`errCode` 等排查所需信息 |

日志级别对应：

- `INFO`：正常阶段，如开始选择、任务创建、进度、成功
- `WARN`：可疑但未失败，如超时心跳、取消、超限
- `ERROR`：明确失败，如上传回调失败、云函数返回失败

## 脱敏要求

- 不记录 `openid`、手机号、学号、姓名、密钥、token、密码。
- 不记录完整用户身份信息；如确需定位用户，用 `openid` 后四位或内部测试账号代替。
- 临时文件路径可以记录，但提交前确认不包含敏感信息。
- 云函数返回的 `errMsg` 可以记录，但要避免把完整请求体或数据库文档原样贴入。
- 日志中的示例数据统一使用占位值，如 `articleId=xxxxxxxx`。

## 生命周期

- 问题解决后，删除对应临时日志文件。
- 如果有长期参考价值，把结论整理到 `docs/research/`，不要长期保留原始排查日志。
- 本 `README.md` 长期保留，作为日志书写规范。
