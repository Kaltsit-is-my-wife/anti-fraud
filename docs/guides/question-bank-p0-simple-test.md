# 题库 P0 修复简易测试说明（大白话版）

适用：2026-11-17 的题库修复，主要测三件事：

1. 5 个、6 个选项的题能不能正常答。
2. 草稿/下线题库会不会被普通用户抽到。
3. 题目超过 100 道后，管理端还能不能看到全部。

## 一、先做两件事

1. 在微信开发者工具里重新部署这些云函数（右键目录 → 上传并部署：云端安装依赖）：
   - `getQuizQuestions`
   - `submitQuizAttempt`
   - `saveQuizQuestion`
   - `importQuizQuestions`
   - `getQuizQuestionList`
   - `getAdminQuestionBankList`
   - `getQuestionBanks`
   - `saveQuestionBank`
   - `deleteQuestionBank`
   - `initQuestionBanks`（如果你们用过这个初始化函数）
2. 重新编译小程序。

准备两个账号：管理员（`isAdmin: true` 或 `roles` 里有 `operator`）和普通用户。

---

## 二、测 5/6 选项题

### 测 5 个选项（正确答案 E）

1. 管理员进“题目管理”，新建一道题。
2. 选项写 5 行：A、B、C、D、E。
3. 正确答案索引填 `4`（A=0，B=1，C=2，D=3，E=4）。
4. 保存。
5. 点这道题所在题库的“预览答题”，看选项是不是完整显示 A–E，正确答案是不是 E。
6. 把题库发布出去，普通用户进去答题，选 E 交卷。

**正常结果：** 保存成功，预览能看到 E，普通用户选 E 后判对。

> 如果题库发布不了，先把题库的“默认抽题数”改成 1，或者多准备几道题。发布校验会检查启用题数量。

### 测 6 个选项（正确答案 F）

把上面步骤重复一遍，选项写 6 行，正确答案索引填 `5`（F=5）。

**正常结果：** 选 F 能交卷，判分正确。

### 测 7 个选项（应该被拦住）

1. 新建题目，选项写 7 行。
2. 点保存。

**正常结果：** 提示“最多支持 6 个选项（A-F）”，保存失败。

> 批量导入也一样，导入 7 个选项的题会报错。

---

## 三、测草稿/下线题库

### 1. 草稿题库不能被普通用户抽到

1. 管理员新建一个题库，状态选 `draft`。
2. 往这个题库里加 1 道启用题（有解析）。
3. 去云开发控制台 → 数据库 → `question_banks`，找到这个题库，复制它的 `_id`。
4. 用普通用户账号，在开发者工具 Console 里执行：

```javascript
wx.cloud.callFunction({
  name: 'getQuizQuestions',
  data: { bankId: '把这里换成草稿题库的_id', count: 5 }
}).then(res => console.log(res.result))
```

**正常结果：**

```text
{ success: false, errMsg: '题库不存在或未发布' }
```

5. 再用普通用户执行交卷：

```javascript
wx.cloud.callFunction({
  name: 'submitQuizAttempt',
  data: {
    bankId: '草稿题库的_id',
    questionIds: ['fake'],
    answers: [0]
  }
}).then(res => console.log(res.result))
```

**正常结果：** 还是提示“题库不存在或未发布”，不会发积分。

### 2. 管理员可以预览草稿题库

管理员在题库管理页点“预览答题”。

**正常结果：** 能正常预览这道题。

普通用户不能预览。用普通账号在 Console 里执行：

```javascript
wx.cloud.callFunction({
  name: 'getQuizQuestions',
  data: { bankId: '草稿题库的_id', preview: true }
}).then(res => console.log(res.result))
```

**正常结果：** 提示“无管理权限，不能预览题库”。

### 3. 发布后普通用户能答，下线后看不到

1. 管理员把题库状态改成 `published`。如果题库里只有 1 道题，先把“默认抽题数”改成 1，否则发布校验会拦住。
2. 普通用户从答题首页进这个题库。

**正常结果：** 题库能看到，能正常答题。

3. 管理员把题库改成 `offline`。
4. 普通用户重新进答题首页。

**正常结果：** 这个题库消失了。

---

## 四、测题目超过 100 道（有题量再测）

如果现在题目没超过 100 道，这一项可以先跳过，等题量上来再测。

1. 用批量导入往一个测试题库里导题。一次最多导 100 道，导两次就能超过 100 道（两次的题干不能重复，重复题会被拦下）。
2. 打开“题目管理”，看列表里能不能看到第 101 道之后的题。
3. 打开“题库管理”，看这个题库的启用题数是不是和实际一致。
4. 点“预览答题”，看能不能正常抽到题。
5. 普通用户进这个题库答题，能正常交卷。

**正常结果：**

- 第 101 道之后的题在管理列表里能看到、能编辑、能停用；
- 题库统计数字对得上；
- 不会因为只读了前 100 道就发布失败或抽不到题。

## 五、测完怎么记

简单记这几项就行：

```text
5 选项题：通过 / 不通过
6 选项题：通过 / 不通过
7 选项题被拦住：通过 / 不通过
草稿题库普通用户抽不到：通过 / 不通过
管理员能预览草稿题库：通过 / 不通过
发布后能答、下线后消失：通过 / 不通过
超过 100 道题管理端还能看全：通过 / 不通过 / 暂未测
```

测试题记得删掉或停用，别留在正式题库里。
