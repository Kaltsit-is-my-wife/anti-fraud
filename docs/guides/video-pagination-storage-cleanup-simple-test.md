# 视频分页和旧文件清理简易测试（大白话版）

这份是给组长快速验收用的，不讲原理，照着点就行。

完整版在 [视频分页与存储清理测试说明](./video-pagination-storage-cleanup-test.md)，遇到细节再去查。

## 一、先做三件事

1. 在微信开发者工具里重新部署这 5 个云函数（右键目录 → 上传并部署：云端安装依赖）：
   - `getVideos`
   - `getAdminVideoList`
   - `saveVideo`
   - `deleteVideo`
   - `cleanupStorageFiles`（这是新函数，必须部署）
2. 重新编译小程序。
3. 准备账号：管理员（`isAdmin: true`）、普通用户各一个；如果要测 operator，再准备一个 `roles` 里只有 `operator` 的账号。operator 只能检查，不能实际删除。

> 正式环境测试前先备份 `videos` 和 `storage_cleanup_tasks`。实际清理会永久删除云存储文件，第一次一定要用测试环境和测试文件。

## 二、测视频分页

### 用户端

1. 首页 → 视频学习。
2. 看第一页：最多 20 条云端视频，另外还会多一条内置的“精选短片”。
3. 往下滑到底，或者点“加载更多”。
4. 看第二页：应该继续出视频，不能和第一页重复。
5. 一直加载到最后一页：应该显示“没有更多了”。
6. 在列表最上面往下拉：应该回到第一页刷新。
7. 点开一个视频再返回：
   - 如果当前是第一页，会重新加载第一页；
   - 如果已经加载到第二页，列表保持在第二页。
8. 确认内置的“精选短片”只出现在第一页，第二页不再出现。

**正常结果：** 能加载更多、不重复、到底显示“没有更多了”。

### 管理端

1. 管理中心 → 视频管理。
2. 第一页最多 20 条。
3. 滚到底或点“加载更多”，能继续加载。
4. 随便编辑一条视频，保存后列表会刷新。
5. 删除一条草稿/已下线视频，列表也会刷新。
6. 准备 21 条以上测试视频时，逐页看一遍，所有 `[TEST]` 视频都能找到。

**正常结果：** 管理端分页正常，编辑/删除后列表是最新的。

## 三、测旧文件清理

先准备 2 条测试视频：

- `[TEST] 清理-替换`
- `[TEST] 清理-删除`

两条都用测试视频文件和测试封面，状态保存为 `draft`。文件要用 `cloud://` 开头的云存储文件；HTTPS 外链不会进清理队列。

> 电脑上的微信开发者工具选不了视频，用真机上传，或者先去云开发控制台上传文件，再把 `cloud://` 文件 ID 填到视频管理页。

### 1. 替换文件

1. 编辑 `[TEST] 清理-替换`，把视频地址或封面换成另一个 `cloud://` 文件，保存。
2. 打开云开发控制台 → 数据库 → `storage_cleanup_tasks`。
3. 看有没有新任务：`status` 是 `pending`，`reason` 是 `replaced`，`eligibleAt` 大约是 7 天后。
4. 去云存储看旧文件：应该还在，没有被立刻删除。

**正常结果：** 队列里有任务，旧文件暂时保留。

### 2. 删除视频记录

1. 删除 `[TEST] 清理-删除`。
2. 看 `videos` 集合：记录没了。
3. 看 `storage_cleanup_tasks`：出现 `pending` 任务，`reason` 是 `record_deleted`。
4. 看云存储：文件还在。

**正常结果：** 删记录不等于立刻删文件。

### 3. 先检查，不删除（dry-run）

清理任务默认要等 7 天。测试时不用真等：

1. 在云开发控制台 → `storage_cleanup_tasks`，找到本次测试任务。
2. 把 `eligibleAt`（就是“允许清理的时间”）改成昨天或更早（只改测试任务）。
3. 如果控制台改不了日期，就删掉这条测试任务，手工加一条相同 `fileId`、`status: pending`、`eligibleAt` 为过去时间的记录。
4. 管理员进视频管理 → 页面底部“存储清理” → 点“检查待清理文件”。

**正常结果：**

- 页面显示待清理数量；
- 云存储文件一个都没少；
- 任务还是 `pending`（等待清理）。

### 4. 真正删除（当前暂未开放）

引用检查已覆盖话题正文配图、文章富文本等字段；实际删除仍默认关闭，管理页不显示“执行清理”按钮。

- 现在只验证 dry-run：显示待清理数量、文件不删除、任务保持 `pending`。
- 等引用检查补齐后，在测试环境配置 `STORAGE_CLEANUP_ALLOW_REAL_DELETE=true` 并恢复入口，再按以下步骤验证：
  1. 管理员先点“检查待清理文件”。
  2. 再点“执行清理”，确认。

**正常结果：**

- 测试文件被删除；
- 任务变成 `deleted`（已删除）；
- 其他没到期的任务不受影响。

### 5. 测“还在用的文件不能被删”

1. 准备一个测试封面文件，让两条视频都用它，比如 `[TEST] 清理-引用A` 和 `[TEST] 清理-引用B`。
2. 只替换 A 的封面，让这个共用封面进入清理队列。
3. 把任务改成到期，先用管理员 dry-run 检查；实际删除需在测试环境配置 `STORAGE_CLEANUP_ALLOW_REAL_DELETE=true` 后再执行。

**正常结果：** 共用封面不会被删，任务变成 `skipped_referenced`（意思是“还有别的地方在用，所以跳过”），B 的封面还能正常显示。

### 6. 测权限

普通用户、operator、管理员分别试：

- 普通用户打开视频管理页：应该提示没权限。
- operator 能点“检查待清理文件”，但看不到“执行清理”按钮。
- operator 如果直接调用实际删除，会提示“仅管理员可以执行实际删除”。
- 管理员默认也只能检查；配置 `STORAGE_CLEANUP_ALLOW_REAL_DELETE=true` 并恢复入口后才可实际删除。

开发者工具 Console 可以直接调：

```javascript
wx.cloud.callFunction({
  name: 'cleanupStorageFiles',
  data: { dryRun: true, limit: 20 }
}).then(res => console.log(res.result))
```

把 `dryRun` 改成 `false` 后，普通用户和 operator 会分别被拦住；管理员在未配置 `STORAGE_CLEANUP_ALLOW_REAL_DELETE=true` 时也会返回“暂不支持实际删除”。

## 四、怎么判断通过

简单记这几项：

```text
用户端能加载更多、不重复：通过 / 不通过
加载到底显示“没有更多了”：通过 / 不通过
管理端能分页、保存后刷新：通过 / 不通过
替换文件后出现 pending 任务：通过 / 不通过
删除视频后记录没了、文件还在：通过 / 不通过
dry-run 只检查不删文件：通过 / 不通过
管理员执行后测试文件被删：通过 / 不通过
共用文件不会被误删：通过 / 不通过
普通用户 / operator 权限正确：通过 / 不通过
```

## 五、卡住了先看这里

- **没有“加载更多”**：`getVideos` 或 `getAdminVideoList` 没重新部署。
- **检查结果一直是 0**：任务还没到 7 天，或者 `eligibleAt` 没改成功；先确认任务真的创建了。
- **看不到“执行清理”**：当前账号不是管理员；operator 只能检查。
- **文件没删掉**：看任务状态。`skipped_referenced` 说明还有别的视频/文章/话题/题库/Banner/社区内容在用；`failed` 看 `lastError` 和云函数日志。
- **删了视频文件马上没了**：说明部署的不是这次代码，或者有别的即时删除逻辑。
- **编辑已发布视频后排序变了**：`saveVideo` 没重新部署。

## 六、测完收拾一下

1. 把 `[TEST]` 开头的已发布视频先改成 `offline`，再删除。
2. 删除 `storage_cleanup_tasks` 里的测试任务。
3. 云存储里剩下的测试文件也删掉。
4. 测试数据不要留在正式环境。
