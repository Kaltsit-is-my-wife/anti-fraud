## 1. 当前现状

当前题库管理已经不是从零开始，已经具备基础可用能力：

- 管理员可创建、编辑题库基础信息
- 管理员可按题库查看题目
- 管理员可新增、编辑、停用题目
- 用户侧可查看已发布题库并进入答题
- 抽题链路已支持按 `bankId` 抽题

当前已存在页面与云函数能力：

| 模块 | 当前能力 | 现状判断 |
|---|---|---|
| 题库管理页 | 新建、编辑、保存题库 | 可用，但偏基础 |
| 题目管理页 | 题库切换、新建、编辑、停用题目 | 可用，但缺筛选和统计 |
| 用户题库入口 | 展示已发布题库、展示题量、进入答题 | 已具备主链路 |
| 抽题云函数 | 按题库抽取启用题目 | 已具备主链路 |

## 2. 当前主要缺口

结合当前代码实现，题库管理还存在以下明显空缺：

### 2.1 题库层缺口

- 没有删除题库能力
- 没有题库封面上传能力，只能手填 `URL / cloud://`
- 没有题量统计字段展示，管理端看不到：
  - 总题数
  - 启用题数
  - 停用题数
  - 难度分布
- 没有发布前校验，无法阻止“已发布题库没有题”或“启用题数小于默认抽题数”

### 2.2 题目层缺口

- 没有搜索功能
- 没有筛选功能
  - 按状态
  - 按难度
  - 按标签
  - 按关键词
- 当前“停用题目”后，管理列表里也看不到停用题，不利于复核和恢复
- 没有防重复题能力
- 没有批量导入能力

### 2.3 用户链路缺口

- 用户侧题库展示依赖实时统计启用题数，但管理端没有同口径统计视图
- 已发布题库即使题量不足，用户仍可能进入答题
- `default_bank` 作为兜底题库仍然存在，说明仍有未归档题目

### 2.4 运维与运营缺口

- 没有题库运营规则说明
- 没有题目质量校验流程
- 没有题库发布前检查项

---

## 3. 建议的管理口径

建议把题库管理明确拆成两层：

### 3.1 题库层

一个题库只回答三个问题：

- 这套题给谁做
- 主题是什么
- 默认抽多少题

建议按“专题/场景/人群”拆题库，例如：

- 大学生反诈基础题库
- 校园贷专题题库
- 刷单返利专题题库
- 求职诈骗专题题库
- 钓鱼链接专题题库

### 3.2 题目层

每道题必须维护这些核心字段：

- 题干
- 选项
- 正确答案
- 解析
- 难度
- 标签
- 所属题库
- 启用状态

### 3.3 发布口径

建议统一以下规则：

- `published` 题库必须至少有 1 道启用题
- `published` 题库的启用题数必须大于等于 `defaultQuestionCount`
- 题目未写解析，不允许标记为可投放
- 同一题库内不允许出现重复题干

## 4. 优先级清单

## P0

### QB-P0-01 题库发布校验

目标：避免发布空题库或题量不足题库。

需要改动：

- `cloudfunctions/saveQuestionBank`
- `cloudfunctions/getAdminQuestionBankList`
- `pages/question-bank-management/question-bank-management`

建议实现：

- 保存为 `published` 时校验该题库启用题数
- 若启用题数小于 `defaultQuestionCount`，禁止发布
- 在题库列表中直接显示“启用题数 / 默认抽题数”

验收：

- 启用题数不足时，题库不能发布
- 管理员可以直接在题库列表看到是否满足发布条件

### QB-P0-02 题目管理列表可见性修正

目标：让管理员能看到停用题和启用题，避免题目一旦停用就“消失”。

需要改动：

- `cloudfunctions/getQuizQuestionList`
- `pages/question-editor/question-editor`

建议实现：

- 管理端查询默认返回全部题目，不再只返回 `isActive !== false`
- 页面增加状态筛选：
  - 全部
  - 启用
  - 停用

验收：

- 停用题仍可在管理端查看
- 可对停用题重新编辑或恢复

### QB-P0-03 题库题量统计

目标：让管理端和用户端对题库状态有统一认知。

需要改动：

- `cloudfunctions/getAdminQuestionBankList`
- `pages/question-bank-management/question-bank-management`

建议新增展示字段：

- 总题数
- 启用题数
- 停用题数
- 默认抽题数

验收：

- 管理端题库列表能直接看到每个题库的题量结构
- 发布前不需要靠人工切换到题目页数题

### QB-P0-04 题库删除/下线能力

目标：题库要能被正式下线或删除，而不是只能一直保留。

建议方案：

- 优先做“下线”
- 再做“删除”

原因：

- 已有关联答题记录时，直接物理删除风险较高
- 先下线能满足大多数运营需求

需要改动：

- 新增 `deleteQuestionBank` 或 `offlineQuestionBank`
- `pages/question-bank-management/question-bank-management`

验收：

- 已下线题库不出现在用户侧
- 管理员仍能在后台查看和重新编辑

## P1

### QB-P1-01 题库封面上传

目标：题库管理体验与话题管理一致，支持直接上传封面。

需要改动：

- `pages/question-bank-management/question-bank-management`

建议实现：

- 复用话题管理页封面上传模式
- 支持“上传封面 / 清空封面 / 手填文件 ID”

验收：

- 管理员可直接上传题库封面
- 上传成功后自动回填 `coverImage`

### QB-P1-02 题目搜索与筛选

目标：题量上来后还能维护。

需要改动：

- `pages/question-editor/question-editor`
- `cloudfunctions/getQuizQuestionList`

建议支持筛选：

- 关键词
- 难度
- 标签
- 状态
- 所属题库

验收：

- 题目超过 100 条后仍能快速定位

### QB-P1-03 题目防重复

目标：避免同一题库出现重复题。

需要改动：

- `cloudfunctions/saveQuizQuestion`

建议实现：

- 保存前按“同题库 + 同题干”做重复校验
- 若题干完全相同则拒绝保存
- 后续可扩展为相似题提醒

验收：

- 同题库内不能重复新增同题干题目

### QB-P1-04 发布前检查面板

目标：让运营在题库页直接判断是否可发布。

建议展示：

- 总题数
- 启用题数
- 默认抽题数
- 是否存在重复题
- 是否存在无解析题
- 是否存在无标签题

验收：

- 管理员在题库页可以直接看到“可发布 / 不可发布”状态

---

## P2

### QB-P2-01 批量导入题目

目标：提升录题效率。

建议格式：

- JSON
- Excel/CSV

建议字段：

- question
- optionA / optionB / optionC / optionD
- answerIndex
- explanation
- difficulty
- tags
- bankId

验收：

- 能一次导入一批题目
- 导入失败有错误提示和失败原因

### QB-P2-02 题库预览

目标：发布前能预览用户实际答题效果。

建议实现：

- 在题库管理页增加“预览答题”
- 直接跳转到 `quiz` 页面并附带预览模式参数

验收：

- 管理员可在不影响正式记录的前提下预览题库抽题效果

### QB-P2-03 运营规则页或说明文档

目标：降低后续维护成本。

建议沉淀内容：

- 标签命名规则
- 难度定义口径
- 发布前检查项
- 停用与删除的区别
- `default_bank` 清理规则

---

## 5. 推荐执行顺序

建议按以下顺序推进：

1. 先做 `QB-P0-02` 和 `QB-P0-03`
   先让管理端看得见、数得清。

2. 再做 `QB-P0-01`
   在看得清基础上补发布校验。

3. 再做 `QB-P0-04`
   让题库具备正式下线能力。

4. 再做 `QB-P1-01` 和 `QB-P1-02`
   补体验和维护效率。

5. 最后做 `QB-P1-03`、`QB-P1-04` 和 `P2` 项
   提升运营质量与规模化维护能力。

---

## 6. 本阶段建议目标

如果只做一轮收口，建议本轮目标定为：

- 管理员能清楚看到每个题库有多少题
- 管理员能区分启用题和停用题
- 空题库或题量不足题库不能发布
- 题库可以下线

做到这 4 点，题库管理就从“能录入”提升到“能运营”。

### 第二包

### 第三包

- 防重复题
- 发布前检查面板
- 批量导入

---

## 8. 结论

当前题库管理已经具备“录入和发布”的基础雏形，但距离“运营可控”还差四个核心能力：

- 统计
- 筛选
- 发布校验
- 下线/删除

建议先收口这四项，再继续做上传、搜索、防重复和批量导入。
