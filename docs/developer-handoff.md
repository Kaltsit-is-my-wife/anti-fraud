# 反诈卫士开发者技术交接手册

> 面向后续开发、运维和发布人员。本文与 `docs/project-handoff.md` 配套使用；本文讲技术细节，用户操作请阅读 `docs/manual/user-manual/`。
>
> 更新时间：2026-10-10

## 1. 接手原则

先建立可回滚基线，再修改功能。首次接手不要直接删除旧云函数、数据库集合或历史数据。任何数据迁移都要先备份并在测试环境验证。

项目当前是微信小程序原生代码，没有统一的 npm 根工程。前端由微信开发者工具编译，后端每个 `cloudfunctions/<name>` 目录独立部署。

## 2. 目录与职责

```text
app.js / app.json / app.wxss   全局启动、页面注册、全局样式
pages/                         用户端和管理端页面
utils/                         缓存、云调用、权限、功能开关等公共逻辑
images/                        图片和 tabBar 图标
cloudfunctions/                独立 Node.js 云函数
cloudfunctions/database.md     数据集合、字段和索引参考
docs/manual/                   用户手册和测试案例
docs/                          产品、部署、运维和交接文档
```

一个页面通常包含 `.js`、`.wxml`、`.wxss`、`.json` 四个文件。修改页面结构时同步检查事件名、数据字段和导航路径；修改云函数返回结构时同步检查所有调用页面。

## 3. 启动和登录流程

1. `app.js:onLaunch` 检查云能力并执行 `wx.cloud.init({ traceUser: true })`。
2. 从本地缓存恢复 `openid` 和 `userInfo`。
3. 调用 `login` 云函数。
4. `login` 根据微信 `OPENID` 查找或创建 `users` 用户，并同步 `public_profiles`。
5. 登录结果写入全局变量和本地缓存。
6. 未绑定学生信息时，应用按时间间隔提示进入 `bind-student`。

修改登录字段时，必须同时检查 `app.js`、`cloudfunctions/login`、`cloudfunctions/getUserInfo`、`pages/user`、`pages/profile` 和数据库文档。

## 4. 云函数调用约定

前端统一使用：

```js
const res = await wx.cloud.callFunction({
  name: '函数目录名',
  data: { /* 入参 */ }
})
```

云函数通常返回：

```js
{ success: true, data: {} }
{ success: false, errMsg: '面向用户的错误信息' }
```

新增或修改接口时记录：权限要求、入参类型、返回字段、失败场景、涉及集合和是否幂等。不要让前端依赖云函数内部数据库对象的完整结构。

## 5. 数据库关键约束

### 用户与公开资料

- `users` 保存学号、姓名、手机号等私密字段。
- `public_profiles` 只保存公开展示字段。
- UID 是 9 位数字，公开资料通常以 UID 作为文档 ID。
- 修改昵称、头像、称号、排行榜字段时，检查两张表是否需要同步。

### 答题与积分

- `quiz_questions` 保存题目。
- `quiz_attempts` 保存每次答题记录。
- `quizPoints` 用于排行榜，含义是累计答对题数。
- 答题商城奖励每日上限为 30 分，日期按北京时间计算。
- 积分变化要写入 `points_records`，避免只修改用户余额而没有流水。

### 内容与审核

- 文章使用 `articles`。
- 社区使用 `posts`、`comments`、`topics`。
- 审核任务使用 `review_tasks`。
- 删除、隐藏、审核通过和拒绝必须保持内容状态与审核记录一致。

### 数据写入规则

仓库约定：

```js
// 指定文档 ID
await db.collection('items').doc(id).set({
  data: { name: 'example' }
})
```

不要在 `set({ data: ... })` 的数据对象中再次写 `_id`，否则可能报“不能更新 id 的值”。部分历史云函数仍有此问题，修复时要重点检查 `followUser`、`equipTitle`、`login`、`initQuizQuestions`、`userSignIn`。

## 6. AI 助手配置

`cloudfunctions/aiChat/index.js` 从环境变量读取：

```js
process.env.QWEN_API_KEY
process.env.QWEN_MODEL
```

线上配置位置是：微信云开发控制台 → 对应云环境 → `aiChat` 云函数 → 环境变量。

- `QWEN_API_KEY`：必填。
- `QWEN_MODEL`：当前默认 `qwen-vl-plus`。
- `cloudfunctions/aiChat/config.json` 不应写真实密钥。
- 更新环境变量后重新部署 `aiChat`，再测试文本和图片消息。
- AI 请求失败时查看云函数日志、供应商额度、模型名和网络错误。

不要在前端保存或请求通义千问 API Key，所有外部模型请求必须经过云函数。

## 7. 管理端与权限

管理页面包括题库、题目、话题、视频、审核、称号和管理中心。权限不能只依赖页面隐藏：

1. 前端隐藏无权限入口，改善体验。
2. 云函数再次读取当前用户权限并拒绝越权请求。
3. 数据库权限限制直接读取和写入。

新增管理接口时至少测试普通用户、管理员、未登录三种身份。批量导入、批量删除、数据修复函数必须增加参数校验和操作日志。

## 8. 部署流程

### 前端

1. 用微信开发者工具打开项目。
2. 检查 `project.config.json` 的 AppID。
3. 检查云环境是否为目标环境。
4. 编译并检查控制台错误。
5. 上传体验版，使用测试账号回归。
6. 通过体验版后再提交审核。

### 云函数

1. 只部署实际修改过的函数。
2. 在微信开发者工具中右键函数目录。
3. 选择“上传并部署：云端安装依赖”。
4. 检查部署日志和云函数版本。
5. 在体验版中实际调用验证。

不要只上传前端而忘记部署对应云函数，也不要把测试环境的云环境 ID 发布到生产版本。

## 9. 发布回归清单

### 用户端

- 登录、首次注册和已有用户登录。
- 文章列表、分类、搜索、详情和收藏/阅读记录。
- AI 文本问答、图片分析、异常提示。
- 发帖、评论、关注、站内消息。
- 答题判分、答题记录、排行榜和积分上限。
- 签到、补签卡、双倍积分卡和积分流水。
- 学生绑定、资料修改、称号和成就。
- 视频列表和播放失败提示。
- 诈骗反馈提交和状态展示。

### 管理端

- 管理员登录和权限判断。
- 题库新增、编辑、删除、导入、关联题目。
- 话题发布、编辑、关闭和评论管理。
- 视频新增、编辑、上下架。
- 审核任务领取、通过、拒绝和不存在源内容提示。
- 普通用户无法调用管理员云函数。

## 10. 故障排查

### 页面提示“云函数调用失败”

检查函数名、部署状态、当前云环境、函数日志和入参字段。

### 登录后资料为空

检查 `login` 是否成功、用户是否有 UID、`public_profiles` 是否同步，以及本地缓存是否为旧数据。

### AI 显示未配置

检查云开发控制台中的 `QWEN_API_KEY`，确认变量属于当前环境和 `aiChat` 函数；修改后重新部署。

### 积分不一致

同时检查 `users.points`、`points_records`、答题奖励日期字段和是否发生重复提交。不要直接手工改余额而不补流水。

### 题库或列表为空

检查集合是否存在、状态字段是否为发布状态、分页参数、数据库索引和云函数返回字段。

### 发布后仍是旧逻辑

确认部署的是正确云环境，并在开发者工具清缓存、重新编译；云函数需要单独重新部署。

## 11. 数据迁移和高风险函数

以下函数运行前必须备份，并记录运行时间、操作者、参数和结果：

- `clearUserData`
- `fixUserData`
- `migrateUserUID`
- `fixArticleCategories`
- `convertArticleCategories`
- `fixAllCategory`
- `initAchievements`
- `initProducts`
- `initTitles`
- `initQuizQuestions`
- `importQuizQuestions`

优先使用试运行参数或小批量验证。迁移完成后抽查用户、文章、题目、积分和公开资料。

## 12. 代码修改规范

- 保留源文件顶部模块说明，并在功能变化后更新相关文档。
- 变量和字段沿用现有命名，不要同义新增字段。
- 统一处理空数据、网络失败和重复点击。
- 涉及积分、权限、审核和隐私的修改必须做失败场景测试。
- 提交前运行 JavaScript 语法检查，确认 WXML 事件和页面路径。
- 发布前记录 Git 提交、变更云函数、数据库变更和回滚方式。

## 13. 推荐的首次接手任务

1. 取得微信公众平台、云开发、AI 服务和 Git 权限。
2. 备份当前数据库并保存当前线上版本。
3. 在本地打开项目，确认 AppID 和云环境。
4. 配置 `aiChat` 的云端环境变量并完成 AI 回归。
5. 修复历史云函数中 `set()` 写入 `_id` 的问题。
6. 建立 Git 基线提交，标记体验版和生产版。
7. 按本文发布回归清单执行一次完整测试。
8. 将新发现的问题记录到 `docs/`，不要只保存在聊天记录里。
