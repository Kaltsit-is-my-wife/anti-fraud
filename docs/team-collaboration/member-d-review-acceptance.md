# 成员 D：审查、验收与弱代码编辑

## 你的定位

你是固定的第四人，不承担核心业务开发。你的工作是让 A/B/C 的改动**可审查、可验收、可合并**，把问题挡在合并和发布之前。

## 你的固定职责

### 1. 代码审查

A/B/C 的 PR 合并前必须经过你的审查。重点看：

- 权限校验是否在云函数层完成，而不是只靠前端隐藏
- 内容状态流转是否正确：草稿/下架/待审核不能透出到用户侧
- 云函数返回结构是否和调用方一致
- 数据写入是否包含 `_id`、是否遗漏 `updatedAt`、是否绕过审核
- 错误是否被静默吞掉，是否有可定位的日志
- `CHANGELOG.md` 是否和实际修改一致

### 2. 验收执行

维护 [acceptance-checklist.md](./acceptance-checklist.md)，按批次执行跨模块验收：

- 文章与 CMS 发布状态
- Banner 启用/禁用、排序、图片、链接、降级
- 视频上传、发布、下线、删除、播放、关联跳转
- 话题发布、评论、审核回写
- 题库、题目、答题链路
- 权限矩阵：普通用户、`operator`、`reviewer`、`isAdmin`、未登录

每次验收记录：

- 日期
- 分支/提交
- 开发者工具版本、基础库版本
- 云环境
- 测试账号
- 通过项、失败项、阻塞问题
- 需要补部署的云函数
- 后续跟进分支

### 3. 部署与合并核对

- 管理/审核云函数是否部署到同一目标云环境
- `users`、`videos`、`articles`、`topics`、`question_banks` 等集合是否存在
- `operator` / `reviewer` 测试账号是否配置正确
- `deleteVideo`、文章状态过滤等新函数是否已经部署
- 前端缓存、云存储媒体和小程序环境是否一致

### 4. 弱代码编辑

你可以做：

- 文档、文案、空态、错误态
- 小范围 WXML/WXSS
- `CHANGELOG.md`、`CLAUDE.md`、验收清单
- 明确的低风险小修复

你不要单独做：

- 核心云函数和复杂业务 JS
- 权限模型、发布状态、审核回写
- 数据迁移、批量清理
- A/B/C 负责模块的重构

需要改核心代码时，与对应负责人配对，由对方主改，你审查。

### 5. 合并门禁

每个 PR 合并前至少确认：

- `node --check` 通过
- `git diff --check` 通过
- 微信开发者工具可以编译
- 控制台无新增关键错误
- 变更已在 `CHANGELOG.md` 留痕
- 权限、草稿泄露、敏感数据暴露等阻塞问题已解决

## 当前批次重点关注

### 批次 1

- A：话题发布主链路
- B：审核中心闭环、权限与云环境基线
- D：准备评论状态、审核回写、权限矩阵的验收用例

### 批次 2

- C：题库、题目、视频收口
- D：跨模块回归，确认草稿/下线内容不出现在用户侧

### 批次 3

- B：敏感词规则、角色配置
- C：视频遗留问题
- D：发布前验收和体验版回归

## 协作方式

- A/B/C 提交 PR 时，在描述中写明：改了什么、怎么验证、需要部署哪些云函数
- 你优先看权限、状态流转和数据一致性，再看样式和文案
- 发现问题先复现并记录，不擅自扩大修复范围
- 阻塞问题未解决时不合并，不把“本地通过”写成“线上验收通过”
