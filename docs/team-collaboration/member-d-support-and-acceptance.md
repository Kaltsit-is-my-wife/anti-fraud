# 成员 D：小改动、文档与跨模块验收

## 工作定位

成员 D 不承担大规模功能重构，主要负责改动范围小、风险较低的修复，以及跨模块验收、文档留痕和合并前质量检查。

## 建议分支

```text
fix/topic-cover-preview
docs/content-acceptance
```

根据具体工作创建独立分支，不要把多个无关小修复长期堆在同一分支。

## 可承担的小改动

- 话题管理页封面上传后的预览、列表显示和编辑回显。
- 演示数据提示和空状态文案。
- 低风险页面样式或交互修复。
- 文档、CMS 操作说明和 `CHANGELOG.md` 更新。
- 发现明确的小问题后提交独立修复 PR，不直接改动其他成员负责的核心模块。

## 文档要求

每次修改必须在 `CHANGELOG.md` 记录：

1. 问题场景；
2. 修改方案；
3. 验证结果；
4. 如涉及云函数、CMS、云存储，还要记录部署和环境注意事项。

架构、当前实现事实和长期约束同步维护在 `CLAUDE.md`，但不要在多人并行开发时反复改动同一段内容；可以集中到合并前统一整理。

## 跨模块验收职责

- 使用验收清单验证文章、Banner、视频、话题封面和权限。
- 复现并记录问题，不擅自扩大修复范围。
- 检查普通用户、管理员、审核员和未登录用户的表现。
- 检查云函数是否部署到正确环境。
- 检查页面缓存、云存储媒体和演示兜底是否符合预期。
- 合并前运行语法检查和 `git diff --check`。

## 边界

- 不同时修改成员 A、B、C 的核心业务文件。
- 不负责大型数据迁移、统一媒体清理或全项目重构。
- 不把规划能力描述为已实现能力。
